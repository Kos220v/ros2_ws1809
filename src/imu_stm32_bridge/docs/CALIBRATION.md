# Калибровка

## Что калибруется

1. **Дрейф гироскопа** — снимается автоматически при старте, если во flash
   нет сохранённой калибровки (плату не трогать ~2 с после включения).
   Вручную: команда `GYRO_CALIB` / сервис `~/gyro_calib`.
2. **Магнитометр (hard/soft-iron)** — обязательно на собранном роботе,
   рядом с моторами и проводами. Хранится во flash.
3. **Склонение** — по умолчанию +11.5° (Москва). Узнайте своё на
   magnetic-declination.com и задайте параметром `declination` или командой
   `SET_DECLINATION`, затем `SAVE_FLASH`.

4. **Гейн акселерометра** — не калибруется в текущей версии. У клонов MPU
   бывает отклонение до ~10% (пример: Z = 10.6 м/с² в покое вместо 9.81).
   На ориентацию/азимут не влияет (общий коэффициент сокращается в
   отношениях). Если понадобится точное линейное ускорение — нужна
   поосевая калибровка (отдельная задача).

## Курс плывёт в покое: диагностика и калибровка гироскопа

Почему дрейф возникает именно на плате: по ТЗ курс робота берётся **только**
из кватерниона STM32 (`/imu/data`), ROS-стек (EKF, robot_odom) гироскоп
нигде не интегрирует. Значит, «плывущий угол» — свойство кватерниона платы,
и причина одна из двух (их различает `gyro_drift_check`):

| Вердикт | Признак | Причина | Лечение |
|---|---|---|---|
| `GYRO_BIAS` | курс уплывает с постоянной скоростью, интеграл медианной `wz` совпадает со скоростью дрейфа | смещение нуля MPU6050 (зависит от температуры) | `gyro_calib` + `save_flash` |
| `MAG` | `wz` ≈ 0, а курс блуждает/тянет в сторону | слабый магнитный якорь: калибровка QMC5883L, металл/магниты рядом | `mag_calib_*` (см. ниже), убрать помехи |
| `MOVED` | отклонения от медианы канала > 3 °/с (толчок, качание, вибрация) | робота двигали во время замера | повторить, не касаясь |

Примечание: константное смещение канала (даже огромное, ±5 °/с) — это **не**
движение, а bias, который и нужно калибровать; детектор это учитывает
(медианы в отчёте = оценка смещения нуля по каждому каналу).

### Шаг 1. Измерить дрейф

Робот неподвижен (двигатель обесточен), стек запущен:

```bash
ros2 run imu_stm32_bridge gyro_drift_check --ros-args -p duration_s:=60.0
```

Код возврата 0 — норма, 1 — требует внимания. Пример отчёта:

```
длительность 60 с, курс +12.3° -> +49.5°
скорость уплывания курса: +37.20 °/мин (пороги: warn 1.0, fail 10.0)
средние wz=+0.620 °/с (сигма 0.041), wx=+0.002, wy=-0.001, пик |w|=0.4 °/с
смещения нуля (медианы): wx=+0.001, wy=-0.002, wz=+0.620 °/с; макс. отклонение (рывки) 0.08 °/с
сервис gyro_calib (/imu/imu_stm32_bridge/gyro_calib): найден
ИТОГ: смещение нуля гироскопа — нужна gyro_calib
```

Узел сам проверяет доступность сервиса калибровки: строка
`сервис gyro_calib ...: найден / НЕ НАЙДЕН`.

### Шаг 2. Калибровка гироскопа (вердикт `GYRO_BIAS`)

```bash
# робот ПОЛНОСТЬЮ неподвижен, ~2 секунды:
ros2 service call /imu/imu_stm32_bridge/gyro_calib std_srvs/srv/Trigger
# в логе узла появится прогресс и измеренные смещения:
#   CALIB state=2 progress=100% ... gyro_bias=(..., ..., ...)
# сохранить калибровку во flash платы:
ros2 service call /imu/imu_stm32_bridge/save_flash std_srvs/srv/Trigger
```

Проверка — повторить шаг 1: дрейф должен быть < 1 °/мин (за 10 минут
заезда это ~0.1° — на маршрут не влияет).

Важно:

- Смещение нуля MPU6050 **зависит от температуры**. Калибруйте после
  прогрева платы 5–10 минут и при той же температуре, что будет на заезде
  (откалибровали в холодном гараже — на солнцепёке ноль уплывёт).
- Флаг `gyro_cal` в ежесекундной статистике узла: `True` — смещения учтены.
- `zero_yaw` **не лечит** дрейф — он лишь сбрасывает текущее значение курса.
- Компенсация на стороне навигации: в `navigation.launch.py` работает узел
  `gps_heading` — пока робот едет, курс по перемещению GPS (pose0 в
  `ekf_map`) не даёт дрейфу накапливаться в системе `map`. Дрейф остаётся
  критичным только при долгом движении без GPS-фиксов и для точных
  вращений на месте, поэтому калибровка по-прежнему рекомендуется.
- Вердикт `MAG` калибровкой гироскопа не лечится — переходите к
  магнитометру (следующий раздел) и ищите железо/магниты рядом с платой.

### «waiting for service to become available» — сервис не находится

Сервис моста называется `/imu/imu_stm32_bridge/gyro_calib` (узел
`imu_stm32_bridge` в пространстве имён `imu`, запускается из
`start.launch.py`). Если `ros2 service call` пишет
`waiting for service to become available` и не находит сервис, хотя
`/imu/data` идёт:

```bash
# 1. Виден ли узел и какие у него сервисы:
ros2 node list | grep imu
ros2 service list | grep -i calib

# 2. Кэш графа ros2 CLI мог протухнуть (мост запущен с respawn=True и
#    может перезапускаться): сбросить демон и повторить.
ros2 daemon stop && ros2 daemon start
ros2 service list | grep -i calib

# 3. Сервисов нет вовсе -> работает старая сборка моста или узел не тот:
#    в логе запущенного start.launch.py в первые секунды должна быть
#    строка 'IMU <board> fw ... gyro_cal=...' и ежесекундная статистика.
#    Пересобрать и перезапустить стек:
colcon build --packages-select imu_stm32_bridge
source install/setup.bash
# и перезапустить start.launch.py
```

Если узел виден под другим именем/пространством — подставьте фактическое
имя в вызов, либо передайте его проверялке дрейфа:
`-p calib_service:=/фактический/путь/gyro_calib`.

## Калибровка магнитометра через ROS 2

```bash
ros2 service call /imu/imu_stm32_bridge/mag_calib_start std_srvs/srv/Trigger
# Медленно вращайте РОБОТА ЦЕЛИКОМ ~30 с:
# - полный оборот вокруг вертикальной оси,
# - наклоны вперёд/назад и влево/вправо,
# - переверните вверх ногами, если возможно.
# Прогресс (%) виден в логе узла (сообщения CALIB).
ros2 service call /imu/imu_stm32_bridge/mag_calib_stop_save std_srvs/srv/Trigger
```

Проверка: поле `status` в `/imu/data`... точнее бит `MAG_CAL` в статусе
кадра (виден в логе узла), азимут при повороте на 360° должен проходить
0..360 монотонно без скачков.

Отмена без применения: `mag_calib_cancel`.

## Проверка качества

- Положите робота на стол, покрутите на 90° — азимут должен меняться
  примерно на 90° (сверьтесь с телефонным компасом с учётом склонения).
- Наклоните робота на 20–30° без поворота — азимут должен стоять
  (компенсация наклона работает).
- В логе узла режим должен быть `9x`. Режим `6x` означает проблемы с магом
  (обрыв, переполнение рядом с железом) — курс будет дрейфовать.

## Сброс

- Снять обнуление курса: сервис `~/clear_yaw`.
- Перезаписать калибровки: выполните калибровки заново и `~/save_flash`.
- Полный сброс flash: залейте прошивку с массовым стиранием
  (STM32CubeProgrammer, Full chip erase) — при старте загрузятся defaults.
